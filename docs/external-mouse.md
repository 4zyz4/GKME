# 实体鼠标透传（Android 控制端）

支持 Android 识别的外接 USB、蓝牙鼠标，以及 2.4G 键鼠接收器的鼠标接口。
输入从手机转发给 Wi-Fi 或 USB 主机；不改变手机到主机的协议，不新增自定义映射界面。
蓝牙外设接入手机可以与 Wi-Fi 转发同时使用；这里的蓝牙外设接入与 GKME 的蓝牙 HID
直连模式不同。蓝牙 HID 直连、本机/被控端模式和 Emotion/DSU 连接不启用实体鼠标透传。

## 使用

1. 配对蓝牙鼠标，或通过 OTG 连接 USB 鼠标/2.4G 接收器。
2. 在 GKME 建立 Wi-Fi 或 USB 控制连接，退出设置，回到手柄控制界面。
3. GKME 自动请求 Android pointer capture，手机鼠标光标隐藏，移动和点击转发给主机。
4. 要使用鼠标操作手机设置，请用手机触屏打开 GKME 设置。此时释放捕获并恢复本地光标；
   关闭设置回到控制界面后自动恢复捕获。编辑布局时同样暂停转发。

支持相对移动、左/右/中键、前进/后退侧键、垂直/水平滚轮及按住拖拽。
移动使用捕获事件的相对坐标，避免手机屏幕边缘限制；保留小数移动/滚轮余量。
移动量按 Android 提供的值转发，不能保证获得未经系统处理的原始传感器计数。
侧键需要系统提供相应的 MotionEvent 按键状态；仅生成特殊厂商快捷键的侧键不保证支持。

捕获依赖前台窗口焦点。切后台、系统锁屏、窗口失焦或系统收回捕获时，释放实体鼠标按键。
键盘的 Alt+Tab 等系统快捷键限制仍然存在。GKME 内置纯黑“息屏模式”保持前台，可用于
黑屏操作，但不等于按电源键真正关闭显示屏。

## 状态和兼容性

- `ExternalMousePassthrough` 按设备保存按键与小数余量；多个鼠标的按键取并集。
  拔出一个鼠标不会释放另一个鼠标仍按住的按键，重连不会重放旧移动或滚轮。
- 通过已有 `ConnectionManager.sendMouseReport` 通道进入 ViewModel，在完整 `GamepadInput`
  帧中与触屏/手柄鼠标键位合并。实体鼠标释放不清除其他输入来源的键位。
- 键盘和实体鼠标共用有序 `InputReportQueue`。即使 Ctrl+点击或短点击发生于两个轮询周期
  之间，也保留按下/释放顺序。同一状态下的移动合并，每份相对位移/滚轮只发送一次。
- 原有手柄按钮、摇杆和触控板事件保留原路径。触摸屏、触笔、虚拟设备及声明手柄/
  触控板来源的设备不会进入实体鼠标解码器。对于额外声明摇杆能力的鼠标设备（如
  SPK7328 蓝牙及 YICHIP 2.4G 接收器的 `sources=0x1002313`），允许其鼠标来源、
  `TOOL_TYPE_MOUSE` 的事件，不以键盘类型或是否具有键盘接口作为鼠标判断条件；
  事件本身声明摇杆来源时仍排除。
- 连接已断开时无法向远端保证送达释放；客户端清理状态，远端仍需处理断连释放。
- 接收器占用手机 USB 主机端口时，建议先通过 Wi-Fi 验证。普通 USB Hub 不会自动让手机
  同时充当 USB 主机和通过 ADB 连接电脑的 USB 从设备。

## 自动测试

`./gradlew :android:testDebugUnitTest` 运行 Android 单元测试。

新增测试覆盖移动/滚轮小数累积、快速点击、拖拽、五键状态、重复事件、多个鼠标、取消/
拔出/捕获丢失清理、输入来源排除、大位移拆分、队列合并、Ctrl+点击顺序及 protobuf 合并。

## 实机验收

分别在 USB/2.4G 接收器和蓝牙鼠标下验证：

1. 连续向同一方向移动，确认不会碰到手机屏幕边缘后停住，也不会停止移动后继续漂移。
2. 单击、双击、右键、中键、侧键以及按住左键拖拽，确认松开后不残留按下。
3. 上下滚轮、水平滚轮（如设备支持），确认方向与停止滚动后的行为。
4. Ctrl+点击、Shift+点击和同时使用键盘移动按键，确认修饰键先后顺序。
5. 拖拽中拔出鼠标、打开设置、切后台、锁屏、断线后重连，确认无卡键/旧位移重放。
6. 检查原有触屏鼠标和实体手柄功能；实体鼠标释放不应释放其他来源仍按住的同名鼠标键。

自动测试不能替代手机、实际外设及主机接收端的实机验证。

## 鼠标未转发的诊断

在 Wi-Fi/USB 已连接、退出设置的控制界面移动鼠标并点击、滚轮数次，再用手机触屏进入
设置的连接页，长按连接状态文字复制键鼠诊断。粘贴完整内容可区分设备被筛除、捕获未
生效与窗口/连接条件不满足。诊断记录设备来源与鼠标事件元数据计数，不保存鼠标坐标、
移动轨迹、具体鼠标按键内容或输入文字。打开设置本身会暂停捕获，需以之前事件记录的
状态为准，不能仅根据复制时的 `captured=false` 判断异常。
